# DCL：权限（GRANT / REVOKE）

> **DCL 是"发钥匙收钥匙"**——它决定谁能连数据库、能干什么。四类语言里 DCL 最容易被忽略，却恰恰最重要：**代码如果拿的是 root 权限，出一次事就是全库裸奔。** 本篇的核心就一句话：**最小权限——一个账号只给够用的，别给最高级的。**

## 1. 语法讲透：给权限、收权限

### 1.1 前提：用户从哪来

要给别人发钥匙，**得先有这个人**——数据库用户和系统用户是两回事。MySQL 里要先创建用户，再给权限：

```sql
-- 创建用户 app_user，密码 xxx，只允许从本机登录
CREATE USER 'app_user'@'localhost' IDENTIFIED BY '密码';

-- 以后登录就是：
-- mysql -u app_user -p
```

> **用户名的 `@` 后面是"从哪连"**：`'app_user'@'localhost'` 表示"只能本机连"，`'app_user'@'%'` 表示"从任何机器都能连"。`%` 是通配符，**越宽越危险**——生产环境尽量写成具体的机器，或 `localhost`。

### 1.2 GRANT / REVOKE：给权限 / 收权限

**完整语法三件套：给什么权限、在哪个范围内、给谁。**

```text
GRANT 权限 ON 范围 TO 'user'@'host';
REVOKE 权限 ON 范围 FROM 'user'@'host';
```

```sql
-- 给 app_user"edu_system 库所有表"的只读权限
GRANT SELECT ON edu_system.* TO 'app_user'@'localhost';

-- 收回它的删除权限
REVOKE DELETE ON edu_system.* FROM 'app_user'@'localhost';

-- 改了权限后，刷新让它们立即生效（改完执行一次）
FLUSH PRIVILEGES;
```

**"范围"三档，从宽到窄：**

```text
ON *.*                所有库、所有表            （最宽，≈ 全局）
ON edu_system.*       某个库的所有表            （平时最常用）
ON edu_system.student 某一张表                  （最窄，最精细）
```

**"权限"从低到高，能开几扇门：**

| 权限 | 能干什么 | 类比 |
|---|---|---|
| `SELECT` | 只读 | 看房子的钥匙 |
| `INSERT` / `UPDATE` / `DELETE` | 读写数据 | 搬家具的钥匙 |
| `CREATE` / `ALTER` / `DROP` | 改结构 | **拆房子的钥匙（最危险）** |
| `GRANT OPTION` | 还能给别人发权限 | **配钥匙的钥匙** |
| `ALL PRIVILEGES` | 上面全包 | 万能钥匙（≈ root） |

> **记忆：权限从"只看"到"拆房子"逐级放大。** 给到哪一级，取决于这个用户/这段代码的真实职责——这也是下一节"最小权限"的核心。

## 2. 最小权限原则

**最小权限（Least Privilege）**：每个账号只拿到完成工作所需的最少权限，不多给。

```text
❌ 项目代码统一用 root 连库（配置时最省事，也最危险）
   任何一处 SQL 注入 / 误删，波及全库所有表
✅ app 账号只给 SELECT/INSERT/UPDATE/DELETE
   代码该做的事是读写数据，就别给 DROP——就算出 bug，也拆不了房
```

**三条落地的习惯：**

```text
① 一个角色一个账号
   前端读写 → app 账号（给数据四件套，不给 DDL）
   日常维护 → admin 账号（给 DDL + 数据，不给 GRANT OPTION）
   真正的 DBA → 才拿最高权限

② 够用就好
   只读报表的，只给 SELECT
   要删数据的，才给 DELETE
   拿到建库配置，第一件事就是检查它是不是开了 root

③ 能收回来
   权限给出去就要留 REVOKE 的后路
   "GRANT 一时爽，REVOKE 保平安"
```

> **一句话：数据库安全从 DCL 开始。** 别的语言管"操作对不对"，DCL 管"谁有资格操作"——权限没管好，前面学的 DML/DDL 安全习惯全白搭。

## 3. 常见误区

| 误区 | 真相 |
|---|---|
| "本地开发用 root 方便" | 方便，但**习惯成自然，上了生产还是 root = 全库裸奔** |
| "配置默认给高权限没关系" | **给高权限就是拿全库冒险**。检查配置第一件事：最小权限 |
| "权限给了很难收回" | `REVOKE` 一句话就收回。**权限是可逆的，用起来别手软** |
| "一个项目一个账号就行" | 不同角色（读写 / 维护 / DBA）**分开账号分权限**更安全 |
| "用户随便建，`@'%'` 图方便" | **`@'%'` = 任何机器都能连**。生产环境尽量写成具体机器或 `localhost` |

---

**小结**：DCL 只有两个动词，但管的是**安全边界**。这里最容易翻车的是——**配置默认给了高权限**。记住三个词：**最小权限、分开账号、能收回来。**
