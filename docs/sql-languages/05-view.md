# 视图（VIEW）：把常用的查询存起来

> **视图就是"一条存起来的 SELECT，用起来像一张表"。** 三表联查这种经常要写的复杂查询，写成视图后，以后每次当一张普通表来查就行。**视图本身不存数据**，查它 = 执行里面那条 SELECT。
>
> 前置：建议先读 [01 查询 DQL](./01-dql.md)——视图本质是"把一条 SELECT 存起来"，会用到那里的 JOIN / GROUP BY。

## 1. 视图是什么：一条"存起来的查询"

先说最朴素的理解。你天天写三表联查：

```sql
SELECT s.name AS 学生, c.name AS 课程, sc.score AS 成绩
FROM student_course sc
JOIN student s ON sc.student_id = s.student_id
JOIN course   c ON sc.course_id  = c.course_id;
```

这句很常用，每次都要重写一遍。**视图就是把这句"固化"下来，起个名字**：

```sql
CREATE VIEW v_student_course AS
SELECT s.name AS 学生, c.name AS 课程, sc.score AS 成绩
FROM student_course sc
JOIN student s ON sc.student_id = s.student_id
JOIN course   c ON sc.course_id  = c.course_id;
```

之后查它，就像查一张普通表：

```sql
-- 以前：每次都要写那串 JOIN
SELECT * FROM student_course
JOIN student s ON ... JOIN course c ON ... WHERE sc.score >= 90;

-- 现在：当成一张表，WHERE 直接写在上面
SELECT * FROM v_student_course WHERE 成绩 >= 90;
```

**它和真表的区别，一句话：**

```text
表：   真实存在，占用磁盘，存数据
视图： 一条存起来的 SELECT，本身不存数据，查它 = 执行里面的查询
```

> 关键：**视图不存数据，是"引用"**。底层表的数据变了，查视图看到的跟着变——因为视图每次都是现去底层表取的，没有一份"副本"要同步。

## 2. 语法：建、用、删

**建视图：**

```text
CREATE VIEW 视图名 AS
SELECT ...;              -- 任何一条你写过的 SELECT 都能存进去
```

**用视图：当成一张表。**

```sql
SELECT * FROM v_student_course;                  -- 全查
SELECT * FROM v_student_course WHERE 成绩 >= 90;  -- 还能继续 WHERE 过滤
```

**删视图：**

```sql
DROP VIEW v_student_course;    -- 视图不涉及数据，删了没有数据损失
```

### 2.1 视图是用来查的，不是用来改的

**日常对视图只做 SELECT，不对它做增删改。** 原因有两条，分开说：

**第一，"技术上"很多视图根本改不动。** 视图背后的查询一旦复杂，数据库就不知道该把改动落到哪张表，直接拒绝：

```text
改不动的视图（常见）：
  ① 视图里有 JOIN（多张表拼的）            → 不知道改哪张
  ② 视图里有 GROUP BY / 聚合（COUNT 等）   → 是统计结果，没有"原始行"可改
  ③ 视图里有 DISTINCT / UNION              → 行和底层表不是一一对应

只有极少数"单表、没聚合、列直接对应"的简单视图，技术上才可能改
```

**第二，就算"技术上能改"，也不该用视图改。** 因为改了视图，实际改的是底层表——你看着是一层皮，动的却是底下真正的数据，**行为不透明、容易误导**。

> 所以约定俗成：**视图 = 只读**。查询用视图，增删改直接对底层表做。

## 3. 视图能干什么（为什么值得用）

```text
① 复用：三表联查写一次，之后到处当表用 —— 少写重复 SQL
② 简化：把复杂的查询包成简单的"表"，后面的代码只见这层皮，不用懂底层表结构
③ 权限：只给用户查某个视图，而不给他碰底层表
        —— 比如给运营看 v_student_course，但永远不给底层表的权限（见 04-dcl）
```

**"视图能挡权限"这点值得多说一句。** 视图可以把"能看的部分"单独暴露出来：比如只做一个"不含手机号、不含成绩"的学生视图，再把这个视图的查询权给别人，底层表一个权限都不给。**数据库安全里，视图是"给人看数据但不给底层表"的常见手段。**

## 4. 常见误区

| 误区 | 真相 |
|---|---|
| "视图也会存一份数据" | **视图不存数据**，每次查都去底层表现取；底层表变了视图跟着变 |
| "视图能随便增删改" | **视图是拿来查的**。对它写操作会透传到底层表，行为不直观，别这么干 |
| "视图越多越好" | 视图只是"一条存起来的查询"，**滥用会让查询链越套越深、难排查**——够用就好 |

---

**小结**：视图 = **一条存起来的 SELECT，当表用**。它不存数据、专门拿来查，最大的价值是**复用复杂查询**和**当权限的"挡板"**。
